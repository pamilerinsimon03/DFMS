# DFMS Security Design Gap Report

## Executive Summary & Baseline Reconnaissance (W0)

This report documents the gap analysis between the security design stated in the thesis (Chapters One and Two) and the implementation found in the DFMS codebase. All claims have been verified against the physical source code on October 9, 2026.

### Baseline Environment & Tooling
- **PHP Version:** PHP 8.2.29 (ZTS x64, with `mysqli`, `fileinfo`, `gd`, `imagick`, `mbstring`, `openssl`).
- **Database Engine:** MariaDB 10.4.32 / MySQL Native Driver (`mysqlnd`).
- **PHPStan Static Analysis Baseline:** 2 errors identified (`app/models/Document.php` lines 24 and 354: unused result of static call `Document::processPendingQueue()`).
- **Psalm Static Analysis Baseline:** 0 errors (with default project suppression rules).
- **PHPUnit Test Suite Baseline:** 14 Unit tests executed (11 passed, 3 failed due to disabled rate limiting and partial password/activation migration). Integration tests: 3 passed, 1 test (`ControllerSecurityTest`) stalled due to hardcoded expectation of an external web server running at `localhost:9000`.
- **Document Root Exposure Audit:** When the application runs with the repository root as the web server document root (as evidenced by frontend links pointing to `/public/index.php` and `/app/controllers/...`), direct HTTP GET requests to `/app/config/settings.json`, `/.env`, `/dfms_database.sql`, and `/app/logs/upload_debug.log` returned HTTP 200, exposing database credentials, architectural schemas, and sensitive system logs.

## Systematic Gap Analysis Matrix

|---|----------------------------------|--------|------------------------|-------------------|--------------------------|
| 1 | **Hierarchical Role-Based Access Control** (super_admin > faculty_admin > department_admin > student) | **Partly Met** | `app/utils/AccessControlMiddleware.php:14-19` defines the hierarchy, but middleware fails open (`line 68-70`) on any route not in the whitelist array. | **W4** | Fail-closed policy for all `/app/controllers/` routes; centralized permission matrix config. |
| 2 | **Two-Stage Authorization with Query-Level Scoping** | **Not Met** | `app/utils/AccessControlMiddleware.php:140-148` only inspects `$_GET['doc_id']` and `$_GET['id']`. Controller POST actions (`verifications.php`, `admin.php`) rely on unsanitized `$_POST['doc_id']`. Model queries in `Document.php` and `User.php` perform no query-level scoping. | **W4** | Introduce `AccessScope` helper returning SQL clauses and bound parameters; enforce inside model methods. |
| 3 | **Non-Sequential Exposed Identifiers (UUIDv4)** | **Not Met** | Tables `documents` and `users` exclusively use auto-increment integer primary keys (`dfms_database.sql:35, 74`). URLs (`verification_detail.php?id=1`) and frontend scripts (`dashboard.js`, `verification_detail.js`) expose sequential integers. | **W4** | Add `public_id CHAR(36)` (UUIDv4, unique, indexed) to `users` and `documents`; translate to internal IDs at model boundary. |
| 4 | **Isolated Storage Outside Web Root** (`secure_uploads/session/department/level/`) | **Partly Met** | `app/utils/StoragePathResolver.php:17` places uploads at `__DIR__ . '/../../secure_uploads/'`, resolving inside the repository web root if the web server root is the project root. | **W1** | Introduce `STORAGE_ROOT` and `LOG_ROOT` environment variables defaulting outside the web root; enforce fail-safe boot check. |
| 5 | **HMAC Content Naming & 2-Hex Sharding** | **Not Met** | `app/services/FilenameGenerator.php` uses timestamp-random naming (`doc_123_time_hash.ext`). `StoragePathResolver.php` does not shard by the first two hex characters of the hash nor apply server-side salt HMAC (`hash_hmac('sha256', content, STORAGE_SALT)`). | **W1** | Rewrite `StoragePathResolver` to compute `hash_hmac` with salt, shard by `substr(hash, 0, 2)`, and verify extension via magic bytes. |
| 6 | **Storage Permissions & Traversal Blocking** | **Partly Met** | `StoragePathResolver.php:22` creates directories with `0750` but does not enforce `0640` on files and does not validate `realpath` against `STORAGE_ROOT`. | **W1** | Enforce directory `0750` and file `0640` permissions; validate all resolved paths against `STORAGE_ROOT` using `realpath()`. |
| 7 | **Authenticated File Delivery via Kernel Streaming** (X-Sendfile / X-Accel-Redirect) | **Not Met** | `app/controllers/secure_file_viewer.php:79` and `download_document.php:68` both use PHP `readfile($full_path)`. Neither supports `X-Sendfile` or `X-Accel-Redirect`. | **W2** | Implement `FileDeliveryService` with configurable `SENDFILE_MODE` (`apache`, `nginx`, `php` fallback); deliver zero body from PHP when acceleration is enabled. |
| 8 | **Delivery Defense-in-Depth & Header Security** | **Partly Met** | `secure_file_viewer.php:63` sets `X-Content-Type-Options: nosniff` but lacks Content-Security-Policy headers and does not enforce controller-level scoping or verify pipeline completion/clean status. | **W2** | Enforce strict CSP, verify `file_scan_status == 'clean'`, refuse uncompleted pipeline files, enforce `Content-Disposition: attachment` on downloads, and inline only for verified PDF/images. |
| 9 | **Asynchronous Upload Pipeline Staging Buffer** | **Not Met** | `app/models/Document.php:100-140` moves uploaded files directly into the destination storage path upon HTTP request, triggering queue processing inline. | **W3** | Stage uploads in `STORAGE_ROOT/_staging` (mode 0700); move to permanent storage only after all 3 worker checks pass. |
| 10 | **ClamAV Antivirus Daemon Inspection via INSTREAM** | **Not Met** | `app/services/ClamAVScannerService.php:39` executes `SCAN <path>`, which fails across container/network boundaries, and fails open (`line 29-35`) when socket is unavailable. | **W3** | Rewrite scanner to send chunked `nINSTREAM` socket protocol with 4-byte big-endian framing; fail closed in production; allow bypass only in development with audit log. |
| 11 | **Discrete Laplacian Variance Blur Detection ($\sigma_{Lap}^2 \ge 100$)** | **Not Met** | `app/services/QualityCheckService.php:24, 88` uses kernel `[[-1,-1,-1],[-1,8,-1],[-1,-1,-1]]`, downscales to 400px, calculates standard deviation with threshold 80. PDFs bypass blur check entirely. | **W3** | Normalize width to 800px; convolve with `[[0,1,0],[1,-4,1],[0,1,0]]`; compute variance of response over all pixels; reject below configurable threshold (default 100); rasterize PDF page 1 for testing. |
| 12 | **Tesseract OCR with Regex Field Cross-Check** | **Not Met** | `app/services/QualityCheckService.php:130-180` only checks overall OCR confidence percentage; does not perform regular expression extraction or cross-check matric number/name against student database records. | **W3** | Add `app/config/document_patterns.php`; extract matric, name, exam year, ref number; record `ocr_match_status` and `ocr_extracted` JSON; flag mismatches for administrative review. |
| 13 | **Global Synchronizer Token CSRF Protection** | **Partly Met** | `app/config/config.php:51` defines `requireCSRFToken()`, but it is opted into manually per controller. Token is not accepted from `X-CSRF-TOKEN` header and not verified on PUT/DELETE. `public/activate.php` calls missing `getCSRFTokenInput()`. | **W5** | Globally enforce CSRF validation in `config.php` for all non-GET requests; accept token from `X-CSRF-TOKEN` or POST; inject token in all SPA/XHR requests; make logout a POST request. |
| 14 | **Dual-Engine Sliding Window Rate Limiting** | **Partly Met** | `settings.json` has `"disable_rate_limiting": "1"`. `rate_limits` table exists, but Redis sliding window is not implemented. Limits are not enforced globally at 60/min (general) and 5/min (auth). | **W5** | Implement Redis sliding window rate limiter with transparent database fallback; enforce 60 req/min general and 5 req/min auth endpoints; return HTTP 429 with `Retry-After`. |
| 15 | **Append-Only Tamper-Evident Audit Hash Chain** | **Not Met** | Table `audit_logs` has no `prev_hash` or `entry_hash` columns. Stored procedure `CleanupOldAuditLogs` deletes rows. File-based security logging is not cryptographically chained. No database triggers block modification. | **W6** | Add `prev_hash` and `entry_hash` (CHAR(64)); compute $H_i = \text{SHA-256}(H_{i-1} \parallel E_i)$; add `BEFORE UPDATE` and `BEFORE DELETE` triggers; replace cleanup with archiving; add chain verification script. |
| 16 | **NDPA 2023 & GAID 2025 Statutory Compliance** | **Partly Met** | `consent_records` table exists but is never populated; no consent withdrawal UI for non-core purposes; `users` lacks `processing_restricted`; `retention_rules` missing; `ExportUserData` procedure has broken columns (`file_size`, `file_type`); UI displays outdated NDPR 2019 / NITDA references. | **W7** | Record consent on activation; support withdrawal; add `processing_restricted` gatekeeper; implement retention rules & purge job; fix `ExportUserData`; update regulatory citations to NDPA 2023 / GAID 2025 / NDPC. |
| 17 | **Credential Hygiene & Account Onboarding** | **Not Met** | Seed SQL and README contain default passwords (`admin12345`, `surname12345`). Truncated invalid bcrypt hashes exist in seeds. Password reset accepts leaked raw hashes (`token = ? OR token = ?`). | **W8** | Remove hardcoded passwords; implement `app/scripts/seed_demo.php`; remove surname-based passwords; secure password reset tokens (hash comparison only, single use); deliver activation links via email. |
