# DFMS Security Design Gap Report

## Executive Summary & Baseline Reconnaissance (W0)

This report documents the gap analysis between the security design stated in the thesis (Chapters One and Two) and the implementation found in the DFMS codebase. All claims have been verified against the physical source code on October 9, 2026.

### Baseline Environment & Tooling
- **PHP Version:** PHP 8.2.29 (ZTS x64, with `mysqli`, `fileinfo`, `gd`, `imagick`, `mbstring`, `openssl`).
- **Database Engine:** MariaDB 10.4.32 / MySQL Native Driver (`mysqlnd`).
- **PHPStan Static Analysis Baseline:** 2 errors identified (`app/models/Document.php` lines 24 and 354: unused result of static call `Document::processPendingQueue()`).
- **Psalm Static Analysis Baseline:** 0 errors (with default project suppression rules).
- **PHPUnit Test Suite Baseline:** 14 Unit tests executed (11 passed, 3 failed due to disabled rate limiting and partial password/activation migration). Integration tests: 3 passed, 1 test (`ControllerSecurityTest`) stalled due to hardcoded expectation of an external web server running at `localhost:9000`.
- **Document Root Exposure Audit:** When the application runs with the repository root as the web server document root (as evidenced by frontend links pointing to `/public/index.php` and `/app/controllers/...`), direct HTTP GET requests to `/app/config/settings.json`, `/.env`, `/dfms_database.sql`, and `/app/logs/upload_debug.log` returned HTTP 200, exposing database credentials, architectural schemas, and sensitive system logs.
